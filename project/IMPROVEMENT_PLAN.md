# 改进方案：CARLA × SparseDriveV2 仿真教程

## 一、总纲：统一故事线

**当前问题**：六集各自独立讲知识点，观众能说出一堆名词但形不成可运行的系统图景。

**改进方案**：全系列统一主线——

> 我们要在 CARLA 里跑一个 SparseDriveV2 Agent，用 Bench2Drive 闭环考试验证它能不能安全开车。

这条主线贯穿每集：
| 集 | 在主线中的角色 |
|---|---|
| EP01 | 搭建最小 CARLA 实验，让观众看到一辆车在仿真里跑起来 |
| EP02 | 给这辆车装上 6 相机 rig，理解数据如何从仿真流进算法 |
| EP03 | 理解同步 tick 循环 + Traffic Manager，让"仿真喂算法"可控 |
| EP04 | 为什么选择 Sparse 范式？从 Dense BEV 一路走过来 |
| EP05 | SparseDriveV2 内部怎么把 6 张图变成一条轨迹 |
| EP06 | 把训练好的 checkpoint 放到 CARLA 考场，跑 220 条路线出分 |

每集开场都快速呼应上一集的进展和本集在主线中的位置。

## 二、贯穿系列的统一隐喻

**建议新增一个贯穿系列的视觉母题：Ego 车视角**

- 每集开场和结尾都用"Ego 车从俯视视角行驶在地图上"作为转场锚点
- EP01–03：展示车如何被创建、挂传感器、同步 tick
- EP04–06：展示模型如何从相机输入变成规划轨迹，最后进入 Bench2Drive 考场
- EP06 结尾：Ego 车完整跑完一条路线，展示 DS/SR 分数弹出

这个隐喻让观众始终知道"我们现在在做什么、下一步要加什么"。

## 三、关键概念表述修正

### 3.1 CARLA 与 SparseDriveV2 的关系必须讲清

**当前问题**：前三集讲 CARLA，后三集讲算法，中间缺桥梁。

**修正**：
- EP02 结尾新增一个桥段，明确三句话：
  - CARLA = 闭环仿真环境（提供世界 + 传感器数据）
  - Bench2Drive = 考试协议（220 条路线 + 44 种场景 + 打分规则）
  - SparseDriveV2 = 参加考试的 Agent（6 相机输入 → 轨迹输出）
- EP03 主循环代码中加入"这帧数据最终会喂给 SparseDriveV2"的注释/标注

### 3.2 Ground Truth 必须区分训练和推理

**当前问题**：EP02 说"仿真自动生成 GT"，容易让人误解模型在推理时也能用 GT。

**修正**：
- EP02 Ground Truth 块（#B08）新增一个对比：
  - 训练阶段：GT 做监督信号（模型学习"正确结果是什么"）
  - 推理/闭环评测：模型只能看传感器输入，不能偷看 GT
- 用视觉对比：训练画面显示"GT 标注框"叠加在图像上，推理画面只有原始图像

### 3.3 "端到端"不要讲成黑盒

**当前问题**：EP04 #B03 的表述"一个网络搞定一切"可能误导。

**修正**：
- 改为："端到端 = 训练目标来自最终驾驶效果，梯度从规划回传到感知"
- 强调：内部仍然可以有检测、建图、预测、规划这些**可解释子任务**
- 端到端的核心是**联合优化**而非**结构黑盒**

### 3.4 Sparse 的核心更精准

**当前问题**："只看有意义实体"是对的但不够精确。

**修正**：
- 补充核心机制：Sparse = 用 **learnable queries + geometric anchors** 维护场景状态
- 每个 query 通过 **deformable aggregation** 从多视角图像中采样自己的局部特征
- 计算集中在对象、车道线、候选轨迹这些**关键元素**上，绕开密集 BEV 网格
- 对比例子：Dense BEV 是"先画整张地图再找路"，Sparse 是"直接盯着路上的车和线"

### 3.5 "Scoring is All You Need" 动机提前铺垫

**当前问题**：EP05 直接讲机制，观众不知道"为什么要做这件事"。

**修正**：
- EP04 结尾加一个桥段，提出核心问题：
  - "规划轨迹有两种思路——动态生成，还是从候选池里选？"
  - "生成很灵活但难优化，候选打分很稳定但需要足够密"
  - "SparseDriveV2 的关键问题变成：怎么让候选'足够密'变得可计算？"
- EP05 开场直接回应这个问题，自然引出 Factorized Vocabulary

## 四、分集改进方案

### EP01 — CARLA 仿真器全景

**问题**：偏百科式罗列（地图/版本列表），缺少让观众"跑起来"的最小闭环。

**改进**：

1. **去掉或压缩地图详表**（当前 #B07 的 9 张地图卡片）。只保留"有 10+ 张地图"一句话，重点展示 1-2 张代表性地图的视觉。

2. **新增"最小 CARLA 实验"块**，替换部分罗列内容：
   - 画面展示完整的 8 行 Python 代码：
     ```
     client.connect → world.get_map() → spawn Ego → 
     attach camera → sync mode → world.tick() → apply_control()
     ```
   - 每行代码旁边有对应的 CARLA 渲染画面（车出现、相机画面出现、车开始移动）
   - 观众第一集就知道"后面所有 API 都在拼什么"

3. **开场加入一句话**："这个系列的最终目标是：在 CARLA 里跑通 SparseDriveV2，用 Bench2Drive 考试验证。"

### EP02 — 传感器与数据采集

**问题**：标签和卡片太抽象，传感器如果只靠文字描述会显得像教科书。

**改进**：

1. **传感器展示从"卡片列表"改为"座舱视角 + 多窗口"**：
   - 画面主体是 Ego 车的驾驶视角
   - 周围排列 6 个相机窗口（对应 nuScenes 六相机 rig）：FRONT / FRONT_LEFT / FRONT_RIGHT / BACK / BACK_LEFT / BACK_RIGHT
   - 每讲一种传感器类型，画面切换对应的视觉化输出（RGB 彩色、Depth 灰度、Semantic Seg 伪彩、LiDAR 点云 3D 旋转）

2. **新增"六相机数据流"块**：
   - 展示 6 个 RGB Camera → timestamp/frame id 对齐 → 图像队列 → 模型输入
   - 标注"SparseDriveV2 是纯视觉方案，这就是它的全部输入"
   - 这是连接 CARLA 传感器和 SparseDriveV2 的关键桥梁

3. **Ground Truth 块修正**（按 §3.2）：
   - 左右分屏：左侧"训练模式"（GT 标注叠加），右侧"推理模式"（纯原始图像）
   - 明确标注："闭环评测时，模型只能看原始传感器数据"

### EP03 — 仿真引擎与 API

**问题**：代码展示到位但缺少"同步数据闭环"的完整画面。

**改进**：

1. **主循环可视化改为"同步数据闭环"**：
   - 核心画面是一个环形流程图（而非线性代码块）：
     ```
     world.tick()
       → sensor callback（收集 6 相机 + 其他传感器数据）
       → 同一帧数据对齐 queue
       → model inference（SparseDriveV2 forward）
       → apply_control(throttle, steer, brake)
       → 下一帧 world.tick()
     ```
   - 每一步高亮时，对应代码在旁边闪烁显示
   - 强调：**整个循环必须在 tick 间隔内完成**，否则仿真会掉帧

2. **Traffic Manager 精简**：
   - 保留核心配置代码
   - 增加一个"TM 生成的场景"动画：Ego 前方有车切入、路口有横向来车、行人过马路
   - 不只讲参数，更要展示"这些参数会制造什么样的驾驶场景"

3. **新增 5 秒桥段**："到这一集为止，我们有了世界、传感器和控制循环。下一集开始，我们要进到循环里的那个 model inference 到底是什么。"

### EP04 — 范式演进

**问题**：演进路线讲对了但对比偏静态文字。

**改进**：

1. **核心改进：做强对比动画**
   - **Dense BEV**：画面被网格填满，每个格子发光，大量计算浪费在天空和远处的空白区域
   - **Vectorized**：网格消失，变成几条折线和轨迹，画面干净很多
   - **Sparse**：只剩几个 anchor/query 点在场景里移动，每个点精确附着在目标上
   - 三阶段用同一个场景演绎（同一个路口，三种表示方式），对比一目了然

2. **UniAD 的性能数据精简**：144h/1.8FPS 保留，但不要列参数表。改为视觉对比：UniAD 的慢（画面卡顿）vs SparseDriveV2 的快（画面流畅）。

3. **EP04 结尾新增桥段（按 §3.5）**：
   - 留一个问题给观众："规划轨迹 —— 是让网络当场生成，还是从事先准备好的池子里选？"
   - 引出 EP05 的核心命题

### EP05 — SparseDriveV2 架构

**问题**：全系列最密的一集，参数表太多，动画太少。

**改进**：

1. **减少参数罗列**：Loss function (#B06) 当前是五个公式罗列，改为一句话 + 一个总公式，具体参数不展开到画面上。

2. **强化三个核心动画**：

   **a) Sparse Perception 采样动画（替换当前 #B04 #B05）：**
   - 3D 空间中一个检测 query 的 anchor（蓝色包围盒）
   - 周围生成 8 个采样关键点（绿色小球）
   - 关键点投影到 6 个相机图像平面（6 条投影线动画）
   - 从投影位置提取特征向量，汇聚到 query
   - 这个动画比文字描述直观 10 倍

   **b) Factorized Vocabulary 二维矩阵（替换当前 #B07）：**
   - 横轴 1024 条 Path（不同曲率的彩色曲线）
   - 纵轴 256 条 Velocity Profile（不同斜率的速度曲线）
   - 两者组合瞬间扩展成 262,144 的网格（动画炸开效果）
   - 标注"密集 32 倍，但通过对角线分解变得可计算"

   **c) Coarse-to-Fine 筛选动画（替换当前 #B08）：**
   - 262K 网格中，粗筛阶段：Top-K Path 行高亮（绿色）、Top-K Velocity 列高亮（蓝色）
   - 交叉区域 K² 条轨迹放大进入精选阶段
   - 精选阶段逐条打分，最终一条轨迹高亮为金色（选中）

3. **对比 UniAD 的不再是参数表，而是场景动画**：
   - UniAD 推算慢：画面中车已经开到路口了，上一帧的规划还没算完
   - SparseDriveV2：实时流畅，规划轨迹始终在车前延伸

### EP06 — 闭环评测实战

**问题**：偏"排行榜汇报"，少了"考试全流程"的实战感。

**改进**：

1. **主线从"结果展示"改为"评测流水线"**：
   - checkpoint 文件 → 加载 Agent → 连接 CARLA Server → Bench2Drive 加载 Route → Agent 控车 → 每帧记录 infractions → 最终汇总 DS/SR
   - 这条流水线用动态流程图画出来（每个节点依次点亮）

2. **新增"失败案例"视觉**：
   - 展示真实错误场景（用动画模拟，非实录）：
     - 碰撞前车：画面出现 COLLISION badge（红色闪烁）
     - 闯红灯：画面出现 RED LIGHT badge
     - 压线：画面出现 LANE INVASION badge
     - 超时：画面出现 TIMEOUT badge
   - 每个 penalty 扣分数字弹出，最后汇总到 Driving Score 公式
   - 这个比表格更能让观众理解"闭环评测为什么难"

3. **指标体系从大表格改为逐层构建**：
   - 先展示一条完整路线的行驶动画
   - 路线完成时弹出 Route Completion 进度条
   - 过程中每出现一个违规，Infraction Score 扣减动画
   - 最终 DS = RC × IS 的乘法动画
   - 然后用同样的方式展示 SR 和 Multi-Ability

4. **保留对比数据但精简**：
   - 只保留核心对比表（SparseDriveV2 vs DriveSuprim vs Hydra-NeXt），其他对比移到 EP05
