--- narration ---
我们用同一个路口场景来看三种范式的区别
**Dense BEV** 把整个场景都画满网格，每个点都算
包括路面上方的天空和远处空白，大量算力浪费

**Sparse** 只维护几个附着在目标上的 anchor 点
每个点同时持有可学习的特征和显式的几何锚点
空白区域不算，训练从 144 小时降到 20 小时
推理从 1.8 FPS 提升到 9 FPS

中央展示一个 Detection Query 的工作机制（用较淡的其余 query 作为背景上下文）：
  一个突出的 query 矩形条（宽 320px，高 36px，分为两半）：
  左半 "Feature F" (#58a6ff)，标注 "可学习特征向量"
  右半 "Anchor B" (#3fb950)，标注 "3D 包围盒 (11维)"

[1.5s] 该 query 的 anchor（蓝色 3D BBox）在 3D 空间中定位。
[2s] 围绕 anchor 生成 8 个关键采样点（绿色小球，散布在 anchor 周围）。
[2.5s] 8 条投影线从这些 3D 关键点分别投射到 6 个相机图像平面（每条线的起点是 3D 点，终点在某一个相机视图内的某个像素位置）。
[3s] 从投影位置提取特征向量，汇聚成一条流回到 query 的 Feature 部分。
[3.5s] Feature 部分更新（闪烁一次），表示一轮 refine 完成。

[4s] 底部出现核心公式：
"每个实体 = Instance Feature (F) + Geometric Anchor (B)"
  F 是 "从多视角图像中通过 Deformable Aggregation 采样聚合的可学习表示"，字号 20px，颜色 #8b949e
  B 是 "显式 3D 几何：车辆=11维BBox，车道线=20点Polyline"，字号 20px，颜色 #8b949e

--- narration ---
Sparse 范式的核心机制可以这样理解
每个场景中的实体用一个 query 来表示
query 包含两部分：**可学习的特征向量**和**显式的几何锚点**
关键操作是 **Deformable Aggregation**
每个 query 在它的 3D 锚点周围生成采样关键点
投影到 6 个相机视图上，提取局部特征，聚合回 query
这个 query 就知道"我在哪里、我周围有什么、我该往哪走"
不需要密集 BEV，不需要全场景建模
计算完全集中在有意义的实体上
